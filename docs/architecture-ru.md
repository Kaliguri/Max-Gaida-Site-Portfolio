# Архитектура и конвенции кода — Max Gaida portfolio

Контракт по **коду** (не по визуалу — визуал в [`design-system-ru.md`](design-system-ru.md)).
Задача документа — чтобы не плодились параллельные реализации одного и того же.
Code conventions: the single-source map, so patterns don't get re-implemented.

**Читать перед фичевой работой. Добавил общий паттерн — обнови этот файл.**
Если код расходится с документом — обсуждаем и синхронизируем, молча не расходимся.

---

## 1. Где что лежит (карта)

- `content/` — **единственный источник данных**: профиль, проекты, резюме. Типизировано +
  Zod-валидация на импорте (плохие данные ломают сборку). Данные не дублируем в компонентах.
- `src/lib/` — не-визуальная логика и константы:
  - `site.ts` — метаданные сайта, локали, `NAV` (TOC), `HEADER_NAV` (шапка), `localeHash()`.
  - `motion.ts` — reduced-motion (`prefersReducedMotion()` + хук `useReducedMotion()`).
  - `bento.ts` — `bentoSpan(i)` для равновесных мозаик (soft skills, навыки).
  - `og.ts` — пути и `<meta>`-записи соц-картинок (`ogName`, `ogImagePath`, `ogImageMeta`).
- `src/components/` — UI. Общие примитивы (ниже) не переизобретаем.
- `src/app/` — роутинг (App Router), `[lang]/` — локаль-сегмент, `resume/[role]/print/` — PDF-исходник,
  `[lang]/og/...` — исходники соц-картинок (см. §7).

## 2. Общие примитивы (не переизобретать)

Прежде чем писать инлайн — проверь, нет ли уже:

| Нужно                       | Бери                                                   | Не делай                                               |
| --------------------------- | ------------------------------------------------------ | ------------------------------------------------------ |
| Иконка (outline)            | `components/icons.tsx` (`StrokeIcon` + именованные)    | Инлайн `<svg>` в компоненте                            |
| Ссылка-контакт              | `<ContactLink contact variant>` (`icon`/`pill`/`text`) | Свою `<a>` с `target/rel` логикой                      |
| Поверхность карточки        | `surface-card` / `surface-tile` / `surface-chip`       | `border bg-surface… rounded-… ` строкой                |
| Reduced-motion              | `motion.ts`                                            | `window.matchMedia("(prefers-reduced-motion…")` инлайн |
| Пункты шапки/меню           | `HEADER_NAV` из `site.ts`                              | Хардкод списка ссылок в компоненте                     |
| Якорь на секцию (raw `<a>`) | `localeHash("about")`                                  | `` `/${locale}/#about` `` вручную                      |
| Соц-картинка роута          | `ogImageMeta(lang, ogName.X())` из `lib/og.ts`         | `opengraph-image.tsx` (см. §7) или свой путь к png     |
| Видео проекта               | `<ProjectVideo src poster loop title>`                 | Инлайн `<video controls>` в карточке                   |
| Переход по сайту            | `<Link prefetch={false}>`                              | `<Link>` без флага (см. §10 — RSC-префетч даёт 404)    |
| Растровая картинка          | `.webp` в `public/`                                    | `.jpg`/`.png` (конвертируй, см. §10)                   |

Если понадобилось третье использование чего-то — это сигнал вынести в примитив и вписать сюда.

## 3. Единый источник (single source)

- **Контент** — только `content/`. Появилась строка, которую показываем (тэглайн, роль) —
  она едет в контент, а не хардкодится в JSX.
- **Навигация** — два списка, каждый со своей зоной: `NAV` (левый TOC, полный) и `HEADER_NAV`
  (шапка + мобильное меню, короткий). Шапка и мобилка читают **один** `HEADER_NAV`, layout у них
  разный — данные общие.
- **Спаны bento** (`SUMMARY_SPANS`, `STACK_SPANS` в `page.tsx`) ключуются **по label**, не по
  индексу. Переставили группы в контенте — раскладка не ломается. Индекс-сцепление запрещено.

---

## 4. basePath (деплой-агностичность)

Сайт host-agnostic: `basePath` пустой на кастомном домене, `/Max-Gaida-Site-Portfolio` на голом
github.io (задаётся CI через `NEXT_PUBLIC_BASE_PATH`, см. `next.config.ts`).

- `<Link>` и `next/image` basePath применяют **сами** — им даём app-relative путь
  (`` `/${locale}/resume/...` ``), без базы.
- **Сырые `<a>` Next НЕ переписывает.** Любой рукописный in-site href идёт через `localeHash()`
  (или добавляй базу явно). Это единственный способ не словить битые якоря на github.io.

---

## 5. Движение

- reduced-motion — только через `motion.ts`. Ветка обязательна везде, где есть анимация.
- Прогресс/заполнение (таймбар карусели и т.п.) — `transform` (composited) + `requestAnimationFrame`
  с дельтой по таймстампу, не `setInterval` с фиксированным тиком (иначе низкий FPS/ступеньки).

## 7. Соц-картинки (OG)

Картинки **не** генерирует Next. Файловая конвенция `opengraph-image.tsx` под
`output: "export"` пишет файл **без расширения**, а GitHub Pages отдаёт такие как
`application/octet-stream` — мессенджеры превью не рисуют (проверено на `/CNAME`, 2026-08-21).

Схема вместо неё — та же, что у PDF-резюме:

1. `src/app/[lang]/og/...` — обычные HTML-роуты, рисующие `<OgCard>` размером ровно 1200×630.
   `robots: noindex`, в `sitemap.ts` их нет, со страниц сайта на них не ссылаемся.
2. `scripts/render-og.mjs` (`npm run og`) — после `next build` скриншотит их Playwright'ом
   в `out/og/<lang>/<name>.png`. В CI шаг стоит рядом с `npm run pdf`, до загрузки артефакта.
3. Метаданные роутов берут путь из `ogImageMeta(lang, ogName.X())`, а не пишут его руками.

Следствие: в `next dev` соц-картинки — 404, они появляются только в собранном `out/`. Это
ожидаемо. Новый тип карточки = новый роут под `[lang]/og/` + имя в `ogName` + ветка дискавери
в `render-og.mjs`.

Цвета в `<OgCard>` захардкожены (не токены темы): картинка обязана выглядеть одинаково,
с какой бы темой ни стартовал рендерящий браузер. Крупные `stats` — только короткие значения
(≈10 символов); фразы идут в `facts`, они рисуются мелкой строкой.

## 8. Видео

Один компонент на все случаи — `<ProjectVideo>`. Два слоя, оба обязательны по смыслу:

- **`loop`** — короткое немое превью (≈12 с, 100-250 КБ), играет по ховеру/фокусу вместо
  статичного постера. Под `prefers-reduced-motion` не запускается (`prefersReducedMotion()`).
- **`src`** — полный ролик, грузится **только по клику**, в лайтбоксе с кастомными контролами.
  `preload` у превью — `metadata`, у полного видео — ничего до открытия.

Превью нарезаются ffmpeg'ом из полного ролика:

```
ffmpeg -y -ss 0 -t 12 -i IN.mp4 -an -vf "scale=960:-2,fps=24"   -c:v libx264 -crf 32 -preset slow -pix_fmt yuv420p -movflags +faststart OUT-loop.mp4
```

Файлы лежат в `public/videos/` как `<name>-loop.mp4` рядом с полным `<name>.mp4` и постером
`<name>.jpg`. Данные о клипе — в `content/projects.ts` (`video` у проекта, `caseStudy.videos`
для дев-роликов), схема общая: `projectVideoSchema`.

**В репозитории нет Git LFS** — каждая версия видео остаётся в истории навсегда. Перед тем как
перезаливать ролик, подумай, нужна ли ещё одна копия в истории.

## 9. Аналитика и приватность

Яндекс.Метрика (не Google/Cloudflare — те в РФ режутся), идентификатор счётчика приходит из
`NEXT_PUBLIC_YM_ID`. **Переменной нет — аналитика не грузится вовсе**: локальная разработка и
форки остаются нетронутыми без правок кода. В CI значение подставляется из секрета `YM_ID`
(см. `deploy.yml`).

Баннер — **уведомление, а не согласие** (решение Макса, 21.08.2026): Метрика грузится сразу,
полоска сообщает об этом и ведёт на политику. Блокирующий вариант рассмотрен и отвергнут — он
молча выкидывает из статистики тех, кто баннер проигнорировал, а ради статистики всё и делается.
Юридическая сторона зафиксирована в `content/legal.ts` → `/[lang]/privacy/`.

`<CookieNotice>` и `<Metrika>` живут внутри `<SiteChrome>`, а не в корневом layout — значит
print-роуты (PDF) и og-роуты остаются без счётчика и без баннера. Это важно: иначе Playwright
при рендере PDF и соц-картинок накручивал бы визиты.

Состояние баннера читается через `useSyncExternalStore` (как в `lib/motion.ts`), server-snapshot
= «скрыт». Поэтому в статическом HTML полоски нет, и она не мигает у тех, кто её уже закрыл.

Если на сайте появится форма, ещё один трекер или пиксель — текст в `content/legal.ts`
правится **в том же коммите**. Политика описывает реальное положение дел, а не намерение.

## 10. Производительность и доступность (фаза 7)

Замеряет `npm run lhci` — он поднимает `serve out` и проходит по **явному списку реальных
страниц** (главная, резюме, кейс, политика). Раньше он обходил всё содержимое `out/`, включая
`404.html` и og-карточки: у них SEO 63 просто потому, что их не индексируют, и этот шум прятал
настоящие проблемы.

**Проверяем только баллы категорий**, без `preset`. Пресет `lighthouse:no-pwa` тащит десятки
отдельных аудитов, часть которых на GitHub Pages неисполнима в принципе (`cache-insight` —
заголовками кэша мы не управляем) или относится к сгенерированному Next коду
(`render-blocking-insight`, `legacy-javascript-insight`). Пороги: a11y / best-practices / SEO —
строго **100**, производительность — **≥ 75** (фактически 86-93; запас на более медленный раннер
CI). Шаг в `ci.yml` больше НЕ `continue-on-error` — бюджеты обязаны держаться.

Что было сделано, чтобы туда попасть (и что легко сломать обратно):

- **Вся растровая графика — WebP q82**, ширина ограничена 1600 px
  (`ffmpeg -i IN -vf scale=1600:-2 -c:v libwebp -quality 82 -compression_level 6 OUT.webp`).
  5.6 МБ → 2.3 МБ. Новые скриншоты класть сразу в webp, jpg/png в `public/images` не заводить.
- **Карусель витрины держит в DOM только активный слайд и двух соседей.** Все слайды лежат внутри
  вьюпорта, поэтому `loading="lazy"` их не сдерживает — тормозит именно рендер-гейт. Соседи нужны
  для кроссфейда в обе стороны. Активному слайду `fetchPriority="high"`, соседям `"low"`.
- **Превью-лупы — `preload="none"`**, файл тянется только при первом ховере (`load()` в
  `startPreview`). С `preload="metadata"` четыре ролика начинали грузиться на первой отрисовке.
- **`<Link prefetch={false}>` везде.** На статическом экспорте RSC-payload, который Next
  префетчит, не существует — каждая ссылка в зоне видимости давала 404 в консоли и роняла
  best-practices.
- **a11y-грабли, на которые уже наступили:** `aria-label` в другом падеже, чем видимый текст
  кнопки, ловится как `label-content-name-mismatch` — если текст виден, `aria-label` не нужен
  вовсе; `alt`, дублирующий подпись рядом, — это `image-redundant-alt`, у таких превью `alt=""`;
  ссылка внутри абзаца не должна отличаться только цветом (нужно подчёркивание).

**Остаток, сознательно не тронутый:** LCP главной ~4 с при мобильном троттлинге. Сеть тут ни при
чём (всё догружается к 300 мс) — время уходит в композитинг: `backdrop-blur` шапки, дуотон-портрет,
размытые подложки карусели и галереи. Дальше резать можно только сами эффекты, а это дизайнерское
решение, не техническое.
